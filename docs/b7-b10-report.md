## 01 · 范围

| 项 | 标注平台上的问题 | 需要什么证据 |
|---|---|---|
| B7 | 父子关系与连接对象是否正确 | 预期的连接对象 + 图结构 |
| B8 | 活动零件是否具有对应的运动学关节 | 预期活动件集合 + 关节覆盖 |
| B9 | 运动学关节类型是否正确 | 预期类型 + 声明类型 |
| B10 | 运动学关节的位置与轴向是否正确 | 预期轴向/位置 + 几何 |

**四项都不需要仿真器。** 父子、类型、原点、轴向都是结构事实，资产自己声明了全部
四样；唯一的问题是它们是不是提示词要的那一个。所以这一组是三组里依赖最少、能最早
端到端跑通的。

## 02 · 资产：数据集没有 URDF，但关节图就写在源码里

原计划读 URDF。清点数据仓后发现 `cache/record_materialization/` 从未提交，
**10,788 条记录全部只有 `model.py` 源码**。要拿 URDF 必须先编译，也就是执行数据集
里生成出来的 Python，需要 cadquery 并且应当在隔离环境中进行。

但 B7–B10 不需要 URDF——关节图是直接声明的：

```python
model.articulation(
    "front_flap_hinge",
    ArticulationType.REVOLUTE,        # ← B9 要的关节类型
    parent=cassette,                   # ← B7 要的父连杆
    child=front_flap,                  # ← B7 要的子连杆
    origin=Origin(xyz=(0.0, -0.366, 0.0)),   # ← B10 要的原点
    axis=(-1.0, 0.0, 0.0),             # ← B10 要的轴向
    motion_limits=MotionLimits(lower=0.0, upper=1.1),
)
```

于是实现了**静态 AST 解析器：读它，不跑它**。折叠模块级与函数内常量、展开可折叠的
循环、算出 f-string 拼的关节名、选对能判断的分支。理由三条：不在工作机上执行生成
代码；607 条解析耗时 0.9 秒而编译要数小时；没有环境依赖因此可复现。

| 字段 | 静态可解（607 条 / 2,091 个关节） |
|---|---|
| 关节类型 kind | **100.0%** |
| 轴向 axis | 99.9% |
| 父连杆 parent | 99.2% |
| 原点 origin | 97.4% |
| 子连杆 child | 96.3% |
| **B7–B10 所需字段全齐** | **94.5%**（1,975 / 2,091） |

**解不出来的，记下来、留空、绝不猜。** 一个读不出的原点必须成为「部分覆盖」，
**不能成为 B10 失败**。把「我没测到」报成「资产有缺陷」，正是这套方案要防的头号
错误。旋转过的形状返回「未知」而不是一个错的轴对齐包围盒，因为 B10 要拿它当分母。

几何是短板：只有 **19/607** 条能算出整体包围盒对角线 `D`。

## 03 · 契约：「应该是什么」只能来自提示词

方案否定了拿单一参考资产比对的做法，所以判据只能从提示词里来。这一步用 LLM，但它
**只做翻译，不做判断**——符合「LLM 负责转换，工具负责验证」。

三个关键设计：

- **连接对象（`parent` 字段）**——B7 的真实失败全是连接对象错误。只记「这个零件会
  动」一个都查不出来。
- **引文守卫（`quote` 字段）**——每条 explicit 要求必须附提示词原文逐字片段，加载时
  机械校验，**引文不在原文里直接拒绝**。抽取器没法既编造要求、又编造它的依据。
- **离线冻结**——跑一次存盘，验证器主路径不调 API。可复现、可审计、便宜。

抽取选 Gemini 而非 OpenAI：607 条资产里 **587 条由 OpenAI 模型生成**，同源抽取会
产生误差相关，掩盖「模型误读了提示词」这类真实失败。

结果：**300 条契约，696 个预期关节，682 条 explicit，451 条带连接对象，690 条带
类型，引文守卫违规 0 条。** 花费约 0.35 美元。

## 04 · 四项检测器

### B7 · 父子关系与连接对象

`S = 0.3·子 + 0.4·父 + 0.3·子树纯度`，按可用项重新归一。

**为什么加子树纯度**：榨汁机的推料杆自己的关节完全正确，问题是它挂在盖子的子树里，
盖子一开就跟着跑——只看 parent 查不出来。破壁机的 `release_button` 骑在 `jar` 子树
上，同样靠这一项抓到。

**四个诊断案例全中**：榨汁机（推料杆挂盖子而非料槽）、旋转门（门扇绕店面转，中央
钢柱根本没建）、喷瓶（泵杆和扳机之间没连接）、台钳（凭空造零件承载旋转）。

### B8 · 活动零件是否有关节

`S = 满足数 / 预期数`，加权——引文要求权重 1.0，类别常识要求按自身置信度（≤0.7）。

宽/窄两种定义可切（缺件算不算 B8 失败），见第 06 节。**四项里唯一真正对齐的一项。**

### B9 · 关节类型

`S = 0.6·类型一致 + 0.4·声明自洽`。

**偏离协议**：协议的第二项是「轨迹类型分类器」——跑 FK 看子零件怎么动。**在没有网格
的声明图上这一项是循环论证**：FK 回放的就是关节类型本身，只能永远同意自己。换成
真正独立的证据：声明自洽性（continuous 却带有限限位、revolute 却没有限位、fixed
却带轴向、行程超过一整圈）。

**近似失配：不扣分（推翻了先前的设计）**。revolute↔continuous 原本记 0.4 分，理由
是「该自由旋转的轮子撞到限位就是不能滚」——这个理由在资产语义上仍然成立，但被一个
测量论证击败：契约里的 revolute/continuous 是**抽取模型读散文判的**（全样本 327 vs
119），惩罚它扣的是我们自己抽取器的不确定性，不是资产的缺陷。实测它是 B9 最大的
单一误报来源——**85 处逐关节分歧里占 44 处，且一个真阳性都不贡献**。取消后
FP 20→8、κ −0.038→+0.042、TP 不变。等提示词能直说这个区分时再恢复。

**B9 还剩多少独立内容**：去掉近似失配后，另有 23 处分歧是「资产声明 fixed」——那是
B8 的题；真正的类型不匹配只有 6 处。B9 是否应整项改为 unsupported，待团队决定。

### B10 · 关节原点与轴向

**轴向项**：对着契约的 `axis_hint` 比。只用能在世界系解析的方向词——「vertical side
hinge」算，「about its axle」不算（那是相对几何的方向）。

**锚点项（偏离协议）**：协议用 `d_anchor / D`，需要所有零件都有解析几何，607 条里
只有 19 条满足。但**关节原点就是子零件坐标系的原点**，所以真正该测的是「关节离它要
转动的那个零件有多远」，除以那个零件自己的对角线。只需要一个零件的几何，而且它测的
正是这一项的本意——**铰链长在门外面，就没有装在门上**。

**组合**：可算项的几何平均。协议是连乘；缺一项时连乘会悄悄退化成另一项单独的值、
读起来像完整证据，几何平均保留了连乘的性质又对「靠几项支撑」诚实。

## 06 · 关于标签的三项实证发现

**B9 的标注判的是网格运动，不是声明类型。** 6 条记录声明的类型与契约期望**逐字
相同，人类照样判失败**（主板、办公椅、螺旋瓶盖、厨师机等）。合理解释是标注员在
查看器里看网格怎么动：轴放错位置的 revolute 动起来不像铰链；螺旋瓶盖声明 continuous
字面没错，但真实的拧开是螺旋运动。

**人类的 B8 主要是「缺零件」判断。** 16 条 B8 失败里 **13 条同时判 A3 失败（81%）**。
标注者确认判定依据是「现实中该有的零件没画出来」，属生成侧问题。仅基于提示词的契约
无法覆盖——提示词没写的零件，契约无从知晓。

**十四项在实践中不独立。** **13 条 B9 失败与 10 条 B10 失败，100% 同时失败至少一项
几何或物理指标，无一例外。** B7 失败中 75% 同时失败 A1 与 A2。这对「必须逐项报告」
的论证既是支持也是挑战，需在论文中如实报告。

**缺少双标注**：三位标注者的标注无重叠，人类–人类 κ 无法计算。因此现在无从判断
B8 的 κ=0.093 是「差」还是已经接近标注噪声设定的上限。建议尽快补 10% 双标注。

## 07 · 已被数据排除的路

**「改进名字匹配以降低误报」——实测否定。** 这曾是唯一不依赖几何的重点工作项。
B8 的 63 个误报里 42 个是「找不到对应零件」，但 **7 个真阳性里也有 4 个来自同一个
标志——信号和噪声是同一件事**。模拟把所有这类标志正确解析：κ 从 0.093 到 0.105，
而**召回率从 7/13 塌到 3/13**；配对 bootstrap 5000 次重采样，Δκ 的 95% CI 为
[−0.075, +0.179]，与零无异。B7 更彻底：唯一的真阳性与 41 个误报中的 28 个来自同一
机制，最宽松的匹配器给出 κ=−0.044 且**零个真阳性**。

附带一个更值得注意的观察：一个**严格更正确**的分配规则（修好了一处真实的错误分配）
使 B8 的 κ 从 0.106 降到 0.079、B10 从 0.254 降到 −0.041。**在当前样本量下，代码更
正确与指标更好看已经脱钩**——这本身就是「正例太少」的直接后果。

**校准阈值——买不到东西。** 扫描 τ ∈ [0,1]，最优 κ 仅 0.022 / 0.098 / 0.036 /
0.326，与 τ=0.70 时基本持平。分数根本没把两类分开，问题不在决策阈值而在证据本身。

**靠类别常识救 B8——天花板很低。** 放开抽取器补常识要求的权限后，模型在 31 条上只
补了 2 条（四轮摩托的轮子与悬挂），其余 30 条一条未补。

**无几何做 B9——方向错误。** 标签测的是网格运动。把检测器调到迎合一个测量别的东西
的标签，只会把这个发现藏起来。

## 08 · 偏离协议

| 协议原文 | 改成 | 理由 |
|---|---|---|
| 置信度 `× min(1, \|score−τ\|/0.20)` | 置信度只反映证据可读性，margin 单独记录 | 该项为连续分数设计。这里分数离散，最常见的失败模式恰好落在 0.700 = τ 上，导致 31 条里 23 条弃权。**边界上的分数是一个判断，不是没有判断。** |
| B7 权重 `0.4 子 / 0.3 父 / 0.3 子树` | `0.3 / 0.4 / 0.3` | 按原权重，一个「零件挂到完全错误对象上」的资产得分恰好 0.700，在 0.70 阈值下**判通过**。这一项的名字就叫「连接对象是否正确」，父项权重必须大于 1−τ。 |
| B9 第二项为轨迹类型分类器 | 声明自洽性检查 | 在无网格的声明图上轨迹分类是循环论证。等有几何后应改回协议原文。 |
| （协议未规定）多关节如何聚合 | 四项均取**最差关节** | 取平均时，τ=0.70 意味着资产要坏掉 30% 以上的关节才失败。注入故障检出率：B7 31%→47%、B8 32%→63%、B9 7%→97%、B10 12%→34%。 |

## 09 · 阻塞：几何是三组共同的前置条件

B9 与 B10 的对齐需要网格；B7 的连接对象名称消歧需要网格（「面板」是不是那个叫
`cassette` 的零件，看一眼网格就知道）；归一化常量 `D` 目前仅 19/607 可算。

这个阻塞对另外两组同样成立——**A4/A5/A6 全为几何视觉指标，B11–B14 全需仿真器
输入**。建议在隔离环境中批量编译资产产出 URDF 与网格。

```bash
uv run articraft compile --repo-root . --data-dir ../articraft-data \
  --target visual <record_id>
```

（需 cadquery + articraft SDK，执行的是数据集内生成的 Python，建议在容器/VM 中进行。）

## 11 · 质量保证

**139 个测试全过**，零第三方依赖。

代码经过两轮多智能体审查：

- **对抗审查（42 个 agent）**：提出 38 条发现，经推翻验证后幸存 15 条（12 条 high），
  全部已修复并写成回归测试。最严重的一条：由于要求之间没有排他性，「尾旋翼」可被
  「主旋翼」的关节顶替，导致删掉真实直升机尾旋翼关节后 B8 仍返回
  `1.0 / 通过 / 置信度 1.0 / 失败原因为空`。
- **方向审计（35 个 agent）**：专门回答「还该做什么」，提出 31 条提案，经「证明它
  不值得做」的验证后仅 3 条幸存，且**三条全部是「停止做某事」**。第 07 节与 B9 的
  近似失配改动即来自该审计。

**合成故障注入**（`inject.py`）：真实正例只有 47 个，阈值无法在其上校准，所以从判定
通过的资产上程序化制造已知答案的失败——改父连杆、删关节、换类型、按 5°–90° 梯度
旋转轴向、按 2%–100% 连杆对角线梯度让几何滑离自己的坐标系。它至今抓到三个自身缺陷，
包括「移动关节原点不可能改变锚点距离」这一设计错误。
