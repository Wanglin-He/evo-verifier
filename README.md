# evo-verifier

Evo-Articraft 验证器的 **B7–B10 组**（运动学四项），外加三人共用的地基。

零第三方依赖，Python 3.11+，**139 个测试**。

```bash
uv run --no-project --with pytest python -m pytest -q
uv run --no-project python -m evo_verifier --group B7-B10 stats
uv run --no-project python -m evo_verifier parse <articraft-data 克隆路径>
uv run --no-project python -m evo_verifier --group B7-B10 evaluate <reports 目录>
```

完整实现报告见 [docs/b7-b10-report.md](docs/b7-b10-report.md)——做了什么、量到了什么、
对协议做了哪几处偏离、哪些路已经被数据证伪。

## 模块

**共用地基**（A1–A6 和 B11–B14 两组同样依赖）

| 文件 | 作用 |
|---|---|
| `items.py` | 14 项的冻结定义：项号 ↔ 英文 key ↔ CSV 中文列名 ↔ 族 ↔ 负责人分组 |
| `labels.py` | 标注 CSV → 类型化标签。**空 ≠ 满足**：334 条旧版记录有六列为空 |
| `report.py` | `report.json` 的结构与强制校验、族分数、`Score_full` |
| `evaluate.py` | 逐项 TP/FP/FN/TN、P/R/F1、平衡准确率、Cohen's κ、覆盖率 |

**B7–B10 自己的部分**

| 文件 | 作用 |
|---|---|
| `asset.py` | 静态解析 `model.py` → 零件、关节图、原点/轴向/限位。**不执行代码** |
| `contract.py` | 提示词要求的结构化形式 + 引文守卫 |
| `extract.py` | 一次性离线抽取契约（Gemini），结果冻结到磁盘 |
| `matching.py` | 散文名 ↔ 代码标识符，确定性排他分配 |
| `detectors.py` | B7 / B8 / B9 / B10 |
| `inject.py` | 合成故障注入：真实正例只有 47 个，阈值无法在其上校准 |

**数据**

## 资产从哪来

数据集**没有任何 URDF**——`cache/record_materialization/` 未提交，10,788 条记录
全部只有源码。但 B7–B10 不需要 URDF：关节图直接声明在 `model.py` 里。

静态解析 607 条 / 2,091 个关节：关节类型 **100%**、轴向 99.9%、父连杆 99.2%、
原点 97.4%、子连杆 96.3%，**四项所需字段全齐 94.5%**，耗时 0.9 秒。

解不出来的进 `Asset.notes`、字段留 `None`、**绝不猜**。一个读不出的原点是
「部分覆盖」，**不是 B10 失败**。

几何是短板：只有 **19/607** 条能算出整体包围盒对角线 `D`。

## 结果（300 个真实资产）

| 项 | 正例 | TP | FP | FN | TN | 精确率 | 召回率 | 平衡准确率 | κ | 弃权 |
|---|---|---|---|---|---|---|---|---|---|---|
| B7 | 6 | 1 | 44 | 5 | 168 | 0.022 | 0.167 | 0.480 | −0.010 | 81 |
| B8 | 13 | 7 | 63 | 6 | 187 | 0.100 | 0.538 | **0.643** | **0.093** | 37 |
| B9 | 9 | 1 | 8 | 8 | 108 | 0.111 | 0.111 | 0.521 | 0.042 | 18 |
| B10 | 2 | 1 | 7 | 1 | 66 | 0.125 | 0.500 | **0.702** | **0.164** | 218 |

**B10 与 B8 高于随机；B7 与 B9 与随机没有区别。** 这不是检测器写得不好，是证据
层面的天花板——全量 607 条上，13 条 B9 失败与 10 条 B10 失败**100% 伴随几何或
物理项失败**，标注员判的是网格怎么动。

抽样：300 = 全部 31 条「任一项被判失败」+ 其余 576 条等距抽取 269 条。召回率建立
在全部真实正例上；误报率无偏；精确率被富集，按 40.3% 修正后为 0.010 / 0.053 /
0.030 / 0.091。

## 已被数据排除的路

- **改进名字匹配以降低误报**——B8 的 63 个误报里 42 个是「找不到零件」，但 7 个
  真阳性里也有 4 个来自同一标志。**信号和噪声是同一件事。** 模拟全部正确解析：
  κ 0.093→0.105，召回率 7/13→3/13，配对 bootstrap 的 Δκ 95% CI 含零。
- **校准阈值**——扫描 τ ∈ [0,1]，最优 κ 仅 0.022 / 0.098 / 0.036 / 0.326。
  分数没把两类分开，问题不在决策阈值。
- **靠类别常识救 B8**——放开权限后模型在 31 条上只补了 2 条 prior。
- **不靠几何做 B9**——6 条记录声明的类型与契约逐字相同，人类照样判失败。

## 唯一的出路

**编译资产拿网格。** B9/B10 的对齐需要它，B7 的连接对象名称消歧需要它，`D` 需要
它。这对另外两组同样成立——A4/A5/A6 全是几何视觉项，B11–B14 全需仿真器输入。

## 复现契约抽取

```bash
uv run --no-project python -m evo_verifier --group B7-B10 extract <articraft-data> \
  --out contracts-300 --sample 300 --env-file <含 GEMINI_API_KEY 的 .env>
```

key 只从环境变量或 `.env` 读，走请求头不进 URL。抽取是一次性的，结果冻结在
`contracts-300/`，验证器主路径不调 API。
